# Historical 4.3.1 deferrals

This document records the state of the immutable 4.3.1 rollback baseline. For current behavior, use the [4.4.1 release notes](4.4.1-release-notes.md), [configuration](configuration.md) and [operations guide](operations.md).

## Completed in 4.3.1

- Final TCP/UDP resolved-IP enforcement for `forbidden_ip`, including a bounded, pinned UDP domain cache.
- Strict per-user parsing of `forbidden_ip`, `forbidden_port` and `disconnect_ip`.
- Active TCP/UDP session cancellation after user removal, invalid policy, policy change or credential rotation.
- Durable capture of new traffic while an older database backlog cannot flush.
- Aggregated UDP decryption-failure logging.
- Immutable release-asset handling with an explicit GitHub repository target.

## Deferrals closed by 4.4

- The whole-file JSON outbox was replaced by a transactional SQLite WAL queue with capture-time billing context and canonical payload hashes.
- The traffic marker schema now has an embedded versioned migration and exact startup validation. Version 4.4.1 restores safe automatic initialization for a fresh sshappy-owned schema and directly accepts the exact 4.3.1 table for no-DDL upgrades.
- The MySQL migration is now included in release archives and the read-only documentation directory of the container image.
- Runtime MySQL operations now have explicit context deadlines; normal traffic replay is bounded per cycle and final shutdown captures locally before replay.
- Accounting arithmetic now rejects `int64` overflow, and the SQLite outbox has a process-level single-writer lock plus hardened initialization recovery.

These changes intentionally break local outbox format compatibility. A 4.3.1 JSON outbox must be completely drained and backed up before 4.4 starts; a 4.4 SQLite outbox must be completely drained before rollback. The two versions must never write the same state directory concurrently.

## Still deferred after 4.4

- Exact quota enforcement during an accounting outage. This needs an approved global/per-node reservation and reconciliation contract.
- Node/user speed-limit enforcement. Units, hierarchy, burst, direction sharing, drop/queue behavior and hot-update semantics remain undefined.
- Credential-generation fencing across the narrow handshake/refresh race.
- A distributed safe watermark for automatic MySQL idempotency-marker cleanup.
- Hard outbox batch/byte/age admission limits beyond the current free-space warning.
- Parallel scheduling of independent database work where it can be proven non-reentrant and operationally useful.
- More precise online last-seen updates for stable long-lived flows.
- Additional DNS fallback/stale-cache/multi-address correctness work and malformed-input load testing.
- Native Windows private-DACL packaging and automated image signing policy.
- Production certification on a real Debian 11 amd64 Docker host. The acceptance path must cover TCP/UDP port 1023, plaintext MySQL and graceful shutdown.

The immutable 4.3.1 branch, `v4.3.1` tag and `sadno/sstest:4.3.1` image remain the immediate rollback target. Preserve their exact commit and image digest.
