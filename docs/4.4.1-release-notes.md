# 4.4.1 release notes

Version 4.4.1 is a compatibility hotfix for the 4.4.0 MySQL cold-start regression. Version 4.4.0 connected to MySQL successfully but refused to start unless `sshappy_schema_migrations` had been created manually. That made the container unusable for a direct 4.3.1 upgrade even when its existing `sshappy_traffic_batch` table was fully compatible.

## Fixed

- Default `MYSQL_SCHEMA_MODE=auto` recognizes an exact 4.3.1 traffic-marker table as implicit schema version 1. The migration-record table may be absent and the runtime account needs no DDL permission for this upgrade path.
- If both sshappy-owned auxiliary tables are absent, `sstest` initializes them from the migration embedded in the binary. A schema-specific MySQL advisory lock serializes concurrent first starts.
- Automatic initialization executes three fixed statements separately; it does not enable MySQL multi-statements or load SQL from a writable deployment path.
- Existing tables are inspected before modification and validated again before the migration record is written. Incompatible tables, unknown records and a missing table after version 1 was already recorded remain fatal and are not repaired automatically.
- `MYSQL_SCHEMA_MODE=strict` retains the 4.4.0 controlled-migration behavior with zero runtime DDL.
- MySQL integration tests now cover fresh initialization, an exact 4.3.1 schema with a no-DDL account, strict mode, permission failure, eight concurrent cold starts and existing accounting idempotency.

The 4.4.1 Docker image defaults the database connection to plaintext (`MYSQL_TLS_MODE=disabled`) for this deployment; use it only on a trusted private network. Source-built binaries retain the `auto` fallback. Listener behavior is unchanged: ports `1` through `65535` remain valid, and acceptance uses TCP and UDP port `1023`, never 443.

The 4.4.0 Git tag and Docker image are not overwritten. The hotfix advances only the independent `4.4` branch and is released as `v4.4.1` plus `sadno/sstest:4.4.1`. The repository default branch is not changed before user acceptance.
