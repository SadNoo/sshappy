# sshappy 4.6 release notes

Version 4.6 is based directly on 4.5. It preserves 4.5 database-outage behavior, durable traffic accounting, SS2022 TCP/UDP transport, credential derivation and policy enforcement. No database migration or new runtime environment variable is required.

## Changes

- Enforce the existing node and user `node_speedlimit` fields for TCP and UDP payload traffic.
- Share the node limiter across all users and protocols, and share each user limiter across that user's connections and sessions.
- Keep independent upload and download buckets. The node and user buckets reserve the same interval, so applying both does not serially charge a payload twice.
- Refresh speed-limit snapshots during the existing authorization synchronization. Unchanged buckets survive refreshes, while changed values take effect without a process restart.
- Refresh alive-IP observations for active TCP transfers and long-lived UDP sessions while traffic continues.
- Reject malformed negative or non-finite speed limits without logging credential or full row contents.

## Value semantics

- Unit: decimal Mbps (`1 Mbps = 125,000 payload bytes per second`).
- `0`: unlimited at that scope.
- Node limit: aggregate across all users and TCP/UDP on this node.
- User limit: aggregate across all TCP connections and UDP sessions owned by that user on this node.
- Directions: upload and download are independent and can each reach the configured value.
- Combined limits: the more restrictive node or user availability controls the current transfer.

The limiter uses an internal 100 ms token-bucket burst, with a 2 KiB minimum and 256 KiB maximum. This permits efficient TCP writes and Linux UDP batches without resetting the bucket on each panel synchronization. Traffic accounting remains based on successfully written plaintext payload bytes; waiting or rejected bytes are not billed.

## Compatibility and rollback

The existing schema columns, credential file and traffic-outbox format are unchanged. Preserve `sadno/sstest:4.5` as the immediate rollback image and stop 4.6 gracefully before starting 4.5 against the same state volume.
