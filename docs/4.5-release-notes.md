# sshappy 4.5 release notes

Version 4.5 is based directly on `v4.3.1` (`6f04199458147fd56e3430208d26d01b18738bae`). It intentionally does not include changes from `v4.4.0` or `v4.4.1`.

## Database-network resilience

- A traffic-accounting database failure no longer consumes the authorization fail-closed window. The relay keeps serving while every new accounting interval can be written to the persistent JSON outbox.
- Local outbox persistence failures remain fatal because continuing would lose billable traffic.
- Authorization refresh remains fail-closed after one hour by default. This improves availability on unstable database links but extends the interval during which a revoked or expired user may remain active on the last successful snapshot.
- MySQL advisory-lock waits are capped at five seconds and always remain below the configured I/O timeout.
- A rapidly detected stale pooled connection is retried once on a fresh connection. Full I/O timeouts are retained for the next scheduled replay instead of immediately blocking for a second timeout.
- Accounting errors identify the transaction stage that failed.
- Idle pooled connections expire after 30 seconds.

## Configuration

- MySQL TLS defaults to `disabled`; the standard Docker command no longer needs `MYSQL_TLS_MODE=disabled`.
- The default MySQL I/O timeout is 15 seconds.
- The default authorization stale grace is 3600 seconds.

The plaintext database default is deployment-specific and must be protected by a trusted private network, firewall, or encrypted tunnel. The optional `verify` mode remains available for databases that support TLS.
