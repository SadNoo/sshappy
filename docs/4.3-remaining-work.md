# 4.3 remaining work and explicit deferrals

This branch fixes the high-confidence issues that could be addressed without inventing SSPanel business rules or introducing a mandatory database migration. The following items remain visible rather than being hidden behind broad refactoring.

## Security and authorization

- **Domain form of `forbidden_ip`**: policy currently checks literal target IPs before the outbound resolver runs. A domain that resolves to a forbidden network is not yet rejected at the final resolved address. A complete fix must carry the authenticated user policy into TCP/UDP resolution and validate the exact address used for the connection, including DNS rebinding behavior.
- **Existing TCP connections after user revoke**: credential removal prevents new authentication but does not actively close an already established long-lived TCP connection. A future change should maintain a username-to-connection index or define a maximum connection lifetime/revalidation protocol.
- **Quota during accounting outage**: SSPanel eligibility uses committed database counters. The fail-closed accounting deadline now bounds the outage, but traffic held in memory/outbox is not deducted from authorization queries during that grace period, so a user may temporarily exceed quota. Exact enforcement requires loading an explicit remaining quota and reconciling local pending bytes without double subtraction.
- **Speed limits**: node/user speed-limit fields are loaded but are not enforced. Token-bucket units, burst behavior, hierarchy and hot-update semantics need an explicit product contract before implementation.

## Accounting and storage

- The 4.3 advisory lock serializes concurrent processing of one batch. Automatic marker cleanup is disabled by default because a local process cannot know about another host's old outbox; a future schema should model batch/chunk state explicitly so cleanup can use a proven safe watermark across hosts.
- The JSON outbox rewrites the full queue for each capture/removal and has no hard batch/byte/age bound. A WAL or SQLite queue with compaction and a documented backpressure policy is preferable for long database outages.
- `OUTBOX_MIN_FREE_BYTES` remains primarily an operational warning threshold; it is not yet a complete admission-control policy.
- Startup still creates the idempotency table when absent. Versioned migrations and startup schema compatibility checks should replace runtime DDL before a least-privilege production rollout.

## Runtime and performance

- Online last-seen is refreshed when a connection/session or source address is observed, not continuously for a stable long-lived flow. Activity should be touched from successful traffic with rate limiting.
- Most panel database methods still use driver timeouts rather than per-operation contexts and deadlines, and the main scheduling loop performs database tasks serially.
- UDP session maps retain coarse relay-level critical sections; invalid public UDP packets can still generate high-volume warning logs. Lock sharding and log sampling/rate limiting remain useful hardening work.
- DNS fallback/stale-cache semantics, multi-address routing policy and RFC 2308 SOA minimum handling remain separate correctness improvements.

## Platform, container and deployment

- Non-Unix credential confidentiality still depends on deployment-provisioned filesystem ACLs. Native Windows packaging should add and test an explicit private-DACL policy before being treated as production-ready.
- Application Docker image changes, image builds and publication are intentionally deferred until the 4.3 branch is reviewed and approved.
- The existing Dockerfile still needs a restricted build context, multi-architecture parameters, a non-root runtime and a documented persistent data volume/CA bundle strategy.
- Local validation on macOS cannot execute Linux `sendmmsg`, tproxy or the real MySQL integration path. CI now defines Linux race and disposable-MySQL jobs; their results must be checked after the branch is pushed.

These deferrals should be reconsidered before declaring the project fully hardened. Preserve the 4.2 binary/configuration for rollback; 4.3 keeps the 4.2 outbox JSON and flush-time billing semantics specifically so the stopped 4.3 process's durable queue can be opened by 4.2 without conversion.
